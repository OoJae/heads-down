The quickest way to look "impossible as a web app" is to make Android system surfaces the main way people use the app, with a Solana signature at the end. That means a home-screen widget, a Quick Settings tile, an NFC tap, the text-selection menu or share sheet, and an ongoing notification, each leading into Seeker's own signing step: the Seed Vault Wallet bottom sheet, confirmed by double-tapping the side button and a fingerprint. You can't get this through a PWA. Chrome's Local Network Access restrictions now break wallet connections for TWA/Bubblewrap wrappers, and the MWA repo has open or recent bugs about PWA sessions (#1364, #1458).

Solana Mobile's official 2026 path is Expo React Native with @solana/kit and @wallet-ui/react-native-kit (the wallet-ui project is maintained by judge Beeman), scaffolded with `npx solana-mobile@latest create`, with Solana Mobile's own agent skills and templates such as expo-kit-wallet. The Kotlin Compose scaffold was archived on 13 Aug 2026 and replaced by a kotlin-compose-minimal template. The Kotlin client library (mobile-wallet-adapter-clientlib-ktx 2.0.3) is still maintained; MWA v2.2.0 shipped on 17 Aug 2026 with a Nostr relay transport and a build-tool (AGP 9) update. Flutter is community-maintained and stale (solana_mobile_client 0.1.2, last published about 16 months ago).

Stack recommendation: an Expo SDK 57 app (stable, React Native 0.86) with small custom Kotlin Expo Modules for the widget (built with Glance), the Quick Settings tile, the card-emulation service and the notifications. If the team is Android-native, pure Kotlin and Compose is just as good or better. Expo SDK 58's Android widget support is still in beta (from 15 Sep 2026) and too risky before the 8 Oct deadline.

Seeker constraints:
- **Hardware:** Dimensity 7300, 8 GB RAM, 6.36" 120 Hz AMOLED, 108 MP main camera, Bluetooth 5.4, power-button fingerprint reader.
- **No dedicated crypto button:** the side-button double-tap is the system's Seed Vault gesture.
- **Unconfirmed:** NFC is not listed on the official spec or store pages, and neither is the Android version. Both must be checked on a real device before the core idea depends on them.
- **No Gemini Nano:** Google's on-device models (Gemini Nano / ML Kit GenAI) run only on flagship phones, so on-device AI on Seeker means LiteRT-LM, ExecuTorch or llama.rn running on CPU or Vulkan.

MWA needs a foreground Activity and cannot sign in the background. Every "one-tap from the home screen" flow therefore has to pass through a small invisible launcher screen (a "trampoline" Activity), and any automation needs session keys or capped delegated keys.

Stickiness tailwind: Seeker Activity Tracking scores users on on-chain activity, dApp exploration and daily device use, and feeds SKR rewards, so a daily Seeker ritual is rewarded by the ecosystem itself.

Watch out for repeats. The last hackathon (Monolith, 400+ submissions) already rewarded GPS reward drops (Echo Protocol), a background AI agent (SeekerClaw, built in Kotlin/Compose), camera squat-counting (Kinlog) and AI scavenger hunts (Seek). Close copies will read as less innovative.

IMPLICATIONS_FOR_WINNING:
- Pick one daily loop and run it through 3-4 system surfaces: a widget to see status, a QS tile or App Shortcut for a one-tap action, an ongoing notification during an active session, and an NFC tap or text-selection entry. All of them should end in the Seed Vault double-tap sign. This is exactly what 'use of mobile features' and 'designed mobile-first' reward, and a web app can't show it.
- Script the demo video around the 'phone locked → swipe down → tap tile → bottom-sheet → double-tap → fingerprint → widget updates with haptic' sequence in under 5 seconds. Film it on a real Seeker; that single shot carries the UX and X-factor scores.
- Stack: if the team is TypeScript-first, use Expo SDK 57 (stable) from the expo-kit-wallet template with @wallet-ui/react-native-kit (the official path, maintained by judge Beeman), and write your own Kotlin Expo Modules for the Glance widget, QS tile, HCE and notifications so the GitHub history shows native depth. If the team is Android-native, use Kotlin + Compose + Glance with clientlib-ktx 2.0.3, as SeekerClaw did in winning Monolith. Don't use Flutter, and don't ship on the Expo SDK 58 beta.
- Assume MWA can't sign in the background. Put a translucent launcher Activity behind every system entry point. Anything automatic should use scoped session keys or a Keystore-held burner key with on-chain caps, which also gives the Ethelsec security judges a clear threat model to evaluate.
- Use Seeker-only primitives for trust. SGT plus SIWS gives a Sybil-resistant 'one Seeker = one human' game or reward; .skr names give social identity. Hook into Activity Tracking and SKR so the daily action also moves the user's ecosystem rewards.
- Design for Android 15 on Seeker and check versions at runtime. Use NotificationCompat.ProgressStyle so Live Updates light up on Android 16+ and degrade cleanly on 15. Check NFC presence and on-device AI availability at runtime, and show a fallback in the UI.
- Use Helius for real-time updates: a Helius webhook triggers backend logic that sends an FCM data push to refresh the widget or notification. That keeps widgets live despite the 30-minute update floor, and shows judge Mert's infrastructure in a visible way.
- Put native polish where the camera will see it: 120 Hz animations (Reanimated or Compose), haptics timed to confirmations, generated widget previews, dynamic color, predictive back, and edge-to-edge layout. Judges score UX and presentation at 50% combined.

IDEA_SEEDS:
- 'Clock-In Tile': a QS tile and widget that clock you into a daily commitment (deep work, gym, study). Each clock-in is one double-tap-signed transaction staking a small amount; missing a day forfeits the stake to a pool shared by people who kept their streaks. The widget shows the streak with a Chronometer ticking live, and an ongoing notification shows the active session.

THINGS_TO_AVOID:
- PWA, TWA or WebView-shell wrappers as the core app. The judges score them poorly, and Local Network Access restrictions plus open MWA bugs (#1364, #1458) make wallet connection flaky.
- Building the product around Gemini Nano, AICore or the ML Kit GenAI Prompt API. They are flagship-only (Pixel 9-11, Galaxy S26, Z Fold8/Flip8 and similar), and the Dimensity 7300 Seeker almost certainly returns UNAVAILABLE.
- Assuming NFC, UWB or Android 16 on Seeker without testing on a real device. None of these is listed on the official spec or store pages.
- Live Updates used as crypto price tickers, countdowns to future events or promos. Google's rules explicitly forbid this, and users can revoke promotion.
- Expecting background or silent signing through MWA, or firing a wallet popup for every high-frequency action. Use batching, session keys or capped delegated keys instead.
- Shipping the submission build on the Expo SDK 58 beta just to get Android expo-widgets. Its beta window overlaps the Oct 8 deadline.
- Flutter (stale community MWA client, 0.1.2 from about 16 months ago) and notifee (archived Apr 7, 2026).
- Close copies of recent winners and existing Seeker apps: GPS token drops (Echo Protocol, LootGO), camera squat counters (Kinlog), 24/7 phone AI agents (SeekerClaw), AI scavenger hunts (Seek), and prediction-market feeds (PredictTok, Foresee, Kickr, Cue, which the category is flooded with).
- Treating Platform.constants.Model === 'Seeker' as gating. It can be spoofed; use SIWS plus SGT with mint-level uniqueness.
- Relying on widget updatePeriodMillis for anything 'live' (30-minute minimum). Use pushes or Chronometer views instead.
- Hard-coding priority fees for Bubblegum or Metaplex flows. Seed Vault Wallet may overwrite them with 100k microLamports (issue #1459).
