########## JUDGES-PREFERENCES ##########
SUMMARY: 1. The most useful finding came from the hackathon's own software, not from what the judges have said in public. The public page (solanamobile.radiant.nexus) says judging uses four criteria at 25% each: Stickiness & PMF, UX, Innovation/X-factor, and Presentation & Demo. The judging app is set up differently. As of 2026-09-29, the Align API (align-api.radiant.nexus/hackathons/running) returns six global criteria: AI 20, SKR Integration 20, UX 15, UI 15, Innovation 15, Ecosystem Impact 15. The main track has useGlobalScoring:true, and the judges' scoring screen in the site's code loads exactly these global criteria.
2. The platform also runs an AI pre-screen. Judges see an "AI SCORE" column next to "JUDGE SCORE" and can sort by it. An AI coach reads the deck text, the demo-video transcript and the security audit. It also shows judges an "AI SUGGESTS: top fixes" line for each project, and it flags prompt-injection attempts to judges as a red flag.
3. Radiants built an automated security audit (one per team, public repos only). It checks for about 16 classes of on-chain program bugs, leaked secrets, and known-vulnerable or policy-violating dependencies. It also checks mobile wallet code, including whether the app treats a failed or expired transaction as a success, and whether it logs credentials or links to Android Log. Given the EthelSec judges (Ilias 'A2nkF' Morad is an iOS/macOS kernel exploit developer), code will be read for real.
4. Toly (Solana co-founder): "Mobile is all about consumers", "SocialFi is going to be the next breakout thing" and "You have to build the apps that people want". Since late 2025 he has personally built Percolator, an open-source perps risk engine with 400+ formal proofs and an immutable mainnet deployment ("Reject modernity. Return to open source immutable software."). He values bug-free, formally checked, open-source software with no admin keys.
5. Mert (Helius CEO): his theme for 2025-26 is privacy. Helius bought Light Protocol (2026-06-10) and built Helius Rings, which is devnet-only and in private beta; the SDK is @heliuslabs/zolana 0.2.0-alpha. He also pushes aerospace-grade engineering ("Immutable financial code is akin to a spaceship leaving Earth"), says admin keys are an "illusion of comfort", and sees AI's best crypto use in security rather than agent payments. Helius is also one of the first Seeker "Guardians", the group meant to stop malicious apps.
6. Chase Barker was Solana's first developer advocate. He moved to Solana Mobile in 2025 to "make as many people [ship] apps"; the hackathon now lists him as a Solana Foundation founder mentor. He values real-world apps beyond crypto natives, passion, building in public and public goods.
7. Beeman runs Solana Mobile's official templates, wallet-ui, MWA, the CLI and AI agent skills. His hackathon advice: a working demo beats a flawless one, open source helps, keep the team to 1-3 people, keep the demo to 3 minutes and high level, and engage on X authentically. Akshay Rajan (Solana Mobile business development) has almost no public statements; expect a distribution, partnership and retention lens.
8. The previous hackathon (Monolith) shows what is already crowded. Three of the 10 grand-prize winners (PredictTok, Cue, Foresee) plus one honourable mention (Kickr) were prediction markets. The SKR prize went to AI scavenger hunts (Seek). Other winners were a location-rewards app (Echo), yield aggregators (Cashflow, Backyard Fi), an on-device AI agent (SeekerClaw) and a digital pet (NOMI).
9. The winning profile this points to has a real daily habit loop and SocialFi or consumer appeal with privacy or real safety value. It should also have a genuine (non-decorative) AI feature, a core SKR integration that is not staking, and a small, well-checked, open-source on-chain program with a written threat model. It should pass the automated audit cleanly and have a demo narrated for both humans and the AI transcript reader.

IMPLICATIONS_FOR_WINNING:
- Score well under both rubrics. The public one is 4x25% (Stickiness, UX, Innovation, Demo). The Align judging form may instead show AI 20, SKR 20, UX 15, UI 15, Innovation 15, Ecosystem Impact 15. So the product should have a real AI feature and a real SKR integration, without letting either weaken the core habit loop.
- Make the SKR integration core and not staking. Options: SKR as the unit of wagers, stakes, tips, access or curation; burn or sink mechanics; or paying for AI or compute in SKR. Explain it clearly in the free-text 'skrIntegration' field, which judges see.
- Write for the AI screener as well as the humans. Put explicit, factual criterion-by-criterion claims in the deck text, and narrate the demo clearly because the AI reads the transcript. Run the Radiants security audit early and fix everything so the coach reruns cleanly. Never put reviewer-directed instructions in the materials; that is flagged to judges as a red flag.
- Treat security as a feature for the toly, Mert and EthelSec audience:
- No secrets in the repo; RPC keys go behind a backend or use a client-safe key.
- SIWS with a server nonce, expiry and domain binding.
- SGT verification, not Platform.constants, for any Seeker-gated rewards.
- Show success only after confirmed status with err==null; handle blockheight expiry and timeouts.
- No logging of tokens or intent URIs, and avoid WebView JS bridges.
- Make the on-chain program small, with every Anchor/Quasar account check, no admin withdrawal keys, an immutable-ready upgrade authority, and fuzz/invariant tests (Kani-style proofs if feasible).
- Add a THREAT_MODEL.md to the repo.
- Match toly's stated wants: consumer-first ('Mobile is all about consumers'), SocialFi as the next breakout, internet-capital-markets primitives, open source, and immutable, formally checked code. A consumer social app with an internet-capital-markets angle and an auditable program fits him.
- Match Mert's stated wants: privacy by default (Helius Rings / zolana SDK on devnet, or Token-2022 confidential transfers), bank-grade features 'fully onchain, no compromises', less self-custody intimidation, and trading as where users are. A private payments or social-finance angle on mobile is distinctive and not crowded.
- Stickiness means a daily ritual for crypto-native Seeker owners, who hold SKR and a Seed Vault and are already primed by Activity Tracking and quests to do on-chain actions daily. Design an on-chain action per session that has value on its own, not farm-able quest spam.
- Use native mobile features that PWAs can't: camera/ML on-device, NFC tap between phones, sensors, background services, notifications and widgets, plus Seed Vault through MWA and Seeker Connect. The grants page explicitly calls out sensors, location, cameras and real-time payments.
- Show traction and build in public. The Cashflow winner posted daily build videos on X for 70+ days, Beeman and Chase both value authentic X engagement, and Akshay's business-development lens rewards real users, retention numbers and ecosystem partnerships in the demo.
- Use the official modern stack (solana-mobile CLI templates, @solana/kit, wallet-ui, Seeker Connect, .skr and SGT recipes). Beeman maintains it and will recognize clean MWA wiring. A steady, meaningful GitHub commit history is judged directly.

THINGS_TO_AVOID:
- Prediction-market apps: 3 of 10 Monolith grand prizes (PredictTok, Cue, Foresee) plus honourable mention Kickr were prediction markets, and SKR-winner-style gamified forecasting is everywhere.
- Plain yield aggregators or USDC savings: Cashflow and Backyard Fi already won, and Solana Mobile shipped a first-party USDC Earn Vault in Seed Vault Wallet (2026-08-19).
- A thin 'AI agent on your phone' wrapper around an LLM API: SeekerClaw (MIT, 64 tools) already won and is in the dApp Store.
- Generic GPS scavenger hunts or location-reward drops (Echo Protocol, Seek), fitness move-to-earn (Moonwalk, Kinlog), digital pets (NOMI) and fishing MMOs (Pumpville) unless there is a truly new angle.
- SKR staking integrations: explicitly excluded from the SKR prize.
- PWA or WebView wrappers of web apps, emulator-only demos, and anything that does not install on a real device.
- Security red flags the automated audit and EthelSec will catch:
- Committed keypairs or API keys, and Helius or other RPC keys hardcoded in the APK.
- Rewards gated on Platform.constants.Model.
- SIWS without a server nonce or expiry.
- 'Success' UI shown before on-chain confirmation, or ignoring transaction errors.
- Logging auth tokens.
- WebView JS bridges or exported activities handling untrusted intents.
- Missing signer, owner or PDA checks; unchecked arithmetic; admin keys that can drain user funds.
- Prompt-injection or reviewer-directed text in the deck, README or video; the platform shows it to judges as a red flag.
- Quest-farm or airdrop-bait mechanics posing as stickiness. The judges (Chase, toly) have spoken against low-substance speculation; Mert criticized capital circulating without genuine on-chain apps.
- Over-promising roadmaps without a working core loop; completion is judged from the demo video and technical depth from commit history.
