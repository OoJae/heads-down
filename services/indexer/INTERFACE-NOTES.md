# INTERFACE notes from the indexer workstream

`programs/heads-down/INTERFACE.md` is the contract. It was not edited. Below are the places
where it was ambiguous or incomplete for an indexer, the choice the indexer made, and a
proposed resolution for the lead. Every choice is enforced by a test named in brackets.

## N1. Event byte layout: field widths and slicing (ambiguous → pinned here)

INTERFACE says `sol_log_data`, first byte = tag, and lists field names without widths. The indexer pins:

| Tag | Event | Layout after the tag byte (LE, no padding) | Total |
|---|---|---|---|
| 1 | RigDug | `rig[32] round_id u64 lamports u64 mask u32 ema_ev u64` | 61 B |
| 2 | RigSkipped | `rig[32] round_id u64 error u32` | 45 B |
| 3 | ShiftArmed | `rig[32] shift_id u64` | 41 B |
| 4 | ShiftEnded | `rig[32] shift_id u64 dark_rounds u64 rounds_dug u64 lamports u64 reason u8` | 66 B |
| 5 | SeekerVerified | `rig[32] sgt_mint[32] member_number u64` | 73 B |

- Widths follow the matching account fields (`Rig.shift_id` u64, `ShiftLog.break_reason` u8,
  `SeekerSeat.member_number` u64, ProgramError::Custom is u32, ORE's deploy mask is u32).
- The decoder concatenates every base64 segment of one `Program data:` line, so a single
  `sol_log_data(&[&bytes])` and a multi-slice `sol_log_data(&[&[tag], rig, ...])` decode the same.
- Decoding is exact-length. A different length is recorded as a `BAD_LENGTH` problem, visible in
  `/v1/health`, rather than guessed. [`test/events.test.ts` golden bytes, generated by an independent
  Python `struct` oracle]

**Proposed resolution:** copy the table into INTERFACE.md and add a Rust golden test in the
program that emits these exact bytes.

## N2. `RigDug.lamports` and `RigDug.mask` semantics (ambiguous)

Assumed: `lamports` = SOL actually deployed into squares by this dig (`per_tile × squares ORE
credited`), excluding ORE's Discretionary `fee`; `mask` = squares requested.

ORE skips squares the miner already holds (`deploy.rs:297-299`), so the requested mask and the
deployed mask can differ. The indexer cross-checks every RigDug against the ORE `DeployEvent`
in the same transaction (paired through the Rig PDA of the deploy's `authority`, not by order)
and reports `consistency.lamportsMismatch`. [`test/metrics.test.ts` "flags inconsistencies"]

**Proposed resolution:** emit the post-CPI values (the balance delta the program already computes
for its no-op check, minus the fee) and the mask ORE actually credited.

## N3. Missing events that metrics need

| Gap | Effect today | Proposal |
|---|---|---|
| No event for `register_rig` / `close_rig` | "Total rigs" comes from Rig accounts (getProgramAccounts). A closed rig leaves no trace in current state, so "rigs ever registered" cannot be recomputed from events. | `6 RigRegistered{rig, authority, attestation_level u8}`, `7 RigClosed{rig}` |
| No event for `record_heartbeats` (focus-only shifts, Stack) | Dark rounds of focus-only shifts appear only in the `ShiftEnded` total, with no per-round evidence. | `8 HeartbeatsRecorded{rig, round_id u64, lease_to u64}` |
| `ShiftEnded` has no rounds or timestamps | Dark hours use `dark_rounds ×` the measured median ORE round length (ResetEvent timestamps; 78 s fallback). | Add `start_round u64, end_round u64, mode u8` (they are already in ShiftLog). |
| No `break_shift` / `freeze_rig` events | Pickups are visible only as `ShiftEnded.reason`. | `9 ShiftBroken{rig, shift_id, reason}` |

## N4. Skip error codes for ORE pre-flight skips

INTERFACE step 5 says `dig` pre-flights every ORE abort condition and skips the rig, logged via
an event, but the error list has no codes for those skips: board window closed, miner not
checkpointed, automation underfunded or closing, Motherlode no-op. The indexer shows any
unknown code as `unknown(n)` and counts it.

**Proposed resolution:** add `24 OreWindowClosed`, `25 MinerNotCheckpointed`,
`26 AutomationUnderfunded`, `27 OreNoOp` (or state which existing code each one maps to).

## N5. The gate-open rate is biased by crank pre-filtering (documented, not fixable here)

The crank submits a dig only when its off-chain mirror predicts the gate opens (INTERFACE
"Cadence"), so most closed-gate rounds are never evaluated on chain. The API therefore reports
two separately labelled numbers:

- `gate.openRate` = RigDug / (RigDug + RigSkipped{CostGate}): on-chain evaluations that opened.
  This is biased high by design.
- `gate.digShareOfDarkRounds` = Σ `ShiftEnded.rounds_dug` / Σ `ShiftEnded.dark_rounds`: dug
  rounds as a share of heartbeat-leased rounds.

A true per-round gate rate would need the crank to publish its skip decisions. That is out of
scope for the program.

## N6. Transaction version 1 is live on mainnet

The real ORE reset transaction `4jjLVs2Q…XW3jp` (round 422,680) is a **v1** transaction;
`getTransaction` with `maxSupportedTransactionVersion: 0` fails with error -32015. Every
consumer (indexer, crank, Android history views) must pass `maxSupportedTransactionVersion: 1`.
[`test/fixtures/ore-reset-mainnet-v1.json`, `test/tx.test.ts`]

## N7. ORE facts the indexer relies on (verified against mainnet bytes)

- ORE events are not `Program data:` lines. They are the data of an ORE self-CPI `Log`
  instruction (tag 8) whose only account is the Board, which must sign (`log.rs`, `sdk.rs`
  `program_log`). DeployEvent = 120 bytes, ResetEvent = 144 bytes. Golden-tested on real
  transactions `5uZWBsNQ…MjfQ` (deploy) and `4jjLVs2Q…XW3jp` (reset).
- `DeployEvent.total_squares == popcount(mask)`, and ORE increments `Round.total_miners` only on
  a miner's first deploy with a non-zero amount. The share-of-miners metric therefore counts
  distinct Heads Down authorities with `total_squares > 0` per round, which matches ORE's own
  counting.
- api.ore.com serves `ResetEvent.total_miners` under the name **`num_winners`** (same struct
  position, same value). Checked field by field against the on-chain event. u64 fields such as
  `rng` exceed 2^53 and are parsed exactly.

## N8. Documentation inconsistency (not in INTERFACE.md)

`docs/ORE.md` section 3 says `dig` checks `automation.fee == Config.crank_fee`. INTERFACE.md
says `automation.fee == config.executor_fee`, and Config has both fields. The indexer does not
depend on either, but the two documents should agree.
