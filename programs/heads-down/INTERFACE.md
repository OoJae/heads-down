# `heads_down` program: interface contract v1.3

This is the contract that the program, the crank, the indexer, the registrar and
the Android transaction builders build against. It was **frozen from the
implementation** (`programs/heads-down/program`). Every layout below is the one
the code enforces.

**v1.2 = v1.1 + §11, which is purely additive** (the SKR features: Stack,
Focus Bond, Gift a Rig and the Bury auction). Sections 0 to 10 are the frozen
v1.1 core: no v1.1 instruction layout, account layout, event byte or error code
changed, and every v1.1 golden vector is byte-identical.

**v1.3 = v1.2 + §12, also additive** (mainnet-readiness hardening: governance
rotation, the Rig tombstone, ShiftLog rent recovery, attestation at every
attested check-in). No instruction data, account list, field offset, event
byte or error code of v1.1 or v1.2 moved, and every v1.1 and v1.2 golden
vector is byte-identical. v1.3 fills bytes that were padding or reserved, and
four existing instructions behave differently in ways a client can observe:
§12.1 lists them. Where a sentence in sections 0 to 11 is no longer the whole
story, a "v1.3:" note points to §12.

**Machine-checked source of truth: [`vectors/`](vectors/).** These files are
generated by `tests/src/vectors.rs` from real LiteSVM runs on a fork of live
mainnet ORE. `tests/tests/vectors.rs` fails if they drift by one byte.

| File | What it holds |
|---|---|
| `instructions.json` | Every instruction (32 tags, both auth paths, 47 vectors: 25 v1.1, then 16 v1.2, then 6 v1.3): data hex with a per-field layout, ordered account metas with roles and flags, PDA seeds, the whole transaction, and the executed result with its events |
| `messages.json` | The P-256 preimages, digests, signatures and precompile data |
| `events.json` | Every event layout (tags 1 to 27), with bytes captured from runs and one `RigSkipped` sample per skip code |
| `registrar.json` | The registrar voucher and its Ed25519SigVerify instruction |
| `CROSSCHECK.md` | Where each consumer currently disagrees |

If this document and `vectors/` ever differ, `vectors/` wins and this document
has a bug.

Conventions:

* All integers are **little-endian**. Byte offsets are from the start of the
  account data or instruction data.
* Instruction lengths **include** the tag byte `data[0]`.
* Addresses are 32 bytes. An all-zero address means "none".
* Every instruction requires its exact data length: trailing bytes fail with
  `InvalidInstruction` (0).
* Account-list flags: `s` = must sign, `w` = must be writable.

Program ID: **`HDn4vgLWFLLdexKEwfZwRHjWtizNvdqFteLbMsE67F9p`** (`heads_down::ID`,
Kotlin `HeadsDownProgram.ID`). The deploy keypair lives **outside the repo** at
`~/.config/heads-down/heads_down-program-keypair.json`. Never commit keypairs.

## 0. What changed

### v1.3 (additive; §12)

* **4 instructions**, tags 28 to 31: `propose_governance`,
  `accept_governance`, `cancel_governance`, `close_shift_log`.
* **1 account**, tag 10: RigTombstone (32 bytes, at the Rig PDA).
* **4 events**, tags 24 to 27, and **2 errors**, codes 49 and 50.
* **Config** uses 56 of its 69 tail padding bytes: `pending_governance` at
  192, `pending_governance_eta_slot` at 224, `pending_governance_eta_ts` at
  232 and `pending_eta_ts` at 240. **ShiftLog** uses its 16 reserved bytes at
  112: `payer_prefix`.
* **Every timelock now also waits for 72 hours of cluster time**
  (`Clock.unix_timestamp`), not only for 864,000 slots, which pass in about
  64 hours at mainnet's present slot time. This covers the new rotation and
  `apply_config` (§12.3).
* **`close_rig`** leaves a RigTombstone and **`register_rig`** resumes from it,
  so a rig address never reuses a `shift_id` or accepts an old P-256 message
  again (the §10 re-registration bug, and two replays it hid).
* **`stack_checkin`** re-checks the attestation at attested-only tables.
* The P-256 key-uniqueness marker of THREAT_MODEL §6.8 was evaluated and is
  **not** built (§12.7).
* The mainnet artifact is **SBPFv3** (§12.10).

### v1.2 (additive; §11)

* **13 instructions**, tags 15 to 27: `open_stack`, `join_stack`,
  `stack_checkin`, `settle_stack`, `claim_stack`, `lock_focus_bond`,
  `release_focus_bond`, `forfeit_focus_bond`, `create_gift`, `claim_gift`,
  `refund_gift`, `init_bury_vault`, `bury_auction_buy`.
* **5 accounts**, tags 5 to 9: StackTable, StackSeat, FocusBond, GiftEscrow,
  BuryVault, plus program-owned SPL Token vault ATAs.
* **13 events**, tags 11 to 23. `HeartbeatsRecorded` (8) gains a second
  emitter, `stack_checkin`, with its v1.1 bytes and meaning unchanged.
* **17 errors**, codes 32 to 48.
* **New CPIs**: SPL Token `Transfer` and `CloseAccount`, and ORE `bury`
  (tag 24) signed by the BuryVault PDA. No CPI target is taken from an account.
* SKR is collateral, bond and gift currency. The program mints nothing, emits
  nothing and pays no return for holding SKR; it never touches Solana Mobile's
  SKR staking program.

### v1.1 (from v1)

v1.1 is backwards compatible with every v1 account offset and every v1 event
byte.

* **Instruction layouts.** v1 specified only `dig`. v1.1 specifies all 15
  instructions (§5).
* **Error codes 24..=31**, used for the `dig` pre-flight skips and for
  state-machine errors (§8). `RigSkipped.error` carries the **precise** code,
  including the shared crates' `0x2560_00xx` and `0x5347_00xx` codes.
* **Five new events**, each under a new tag (§7):
  * 6 RigRegistered
  * 7 RigClosed
  * 8 HeartbeatsRecorded
  * 9 ShiftBroken
  * 10 ShiftEndedV2 (a superset of ShiftEnded)

  `ShiftEnded` (tag 4) is byte-identical to v1 and is still emitted.
* **Two new BREAK reasons**: 7 `unplugged` (→ Cooling) and 8 `unlocked`
  (→ Broken).
* **`plan_flags` bit 1 = `DAY`**, which becomes `ShiftLog.mode` 1.
* **Rig reserved bytes now in use** (§3.3): `shift_open`, `break_reason`, the
  cached ORE bumps and `shift_start_ts`.
* **`dig` reserves the Automation fee inside every cap** (§6.4). v1's formula
  omitted the fee.
* **`RigDug.lamports` is the SOL placed on squares**, without the fee.
* **Pausing is immediate.** Un-pausing waits for the timelock.
* **`unfreeze_rig` with an open shift** goes to Broken, not Idle.
* **Measured transaction limits** (§9): 11 rigs per v1 transaction, 5 per v0
  transaction with a lookup table.
* `INTERFACE-NOTES.md` is folded in here and is **superseded**.

## 4. Signed messages

### 4.1 P-256 (verified through the secp256r1 precompile, same transaction)

The signed message is the 32-byte **`SHA-256(preimage)`**.

* **Signing.** Android signs those 32 bytes with `SHA256withECDSA`. The
  precompile verifies ECDSA-P256 over SHA-256 of the same 32 bytes.
* **Recomputation.** The program rebuilds the preimage from its own state plus
  the instruction data, and requires the precompile entry's message to equal
  the digest byte for byte.
* **Signatures and keys.** Signatures are raw `r‖s` in **low-S** form: the
  precompile rejects high-S, and the crank or client normalizes. Public keys
  are 33 bytes, compressed.
* **Counter.** It **strictly increases per rig across all kinds**. Every
  accepted message consumes it: `rig.hb_counter := counter`. One message may
  raise it by at most 2^32 (`MAX_COUNTER_STEP`); a larger jump is
  `InvalidHeartbeat` (6), whatever the signature (§12.13). Clients count up by
  one from the Rig's `hb_counter`.

| Kind | Length | Layout (offset: field) |
|---|---|---|
| HEARTBEAT | 94 | `0 "HDv1" · 4 program_id · 36 rig · 68 kind=1 · 69 counter u64 · 77 shift_id u64 · 85 round_id u64 · 93 lease_rounds u8` |
| BREAK / FREEZE | 86 | `0 "HDv1" · 4 program_id · 36 rig · 68 kind (2 BREAK, 3 FREEZE) · 69 counter u64 · 77 shift_id u64 · 85 reason u8` |
| PLAN | 113 | `0 "HDv1" · 4 program_id · 36 rig · 68 kind=4 · 69 counter u64 · 77 max_ev_cost u64 · 85 dig_lamports u64 · 93 split u8 · 94 solo u8 · 95 lease u8 · 96 flags u8 · 97 window_start i64 · 105 window_end i64` |

* **`shift_id`** is always `rig.shift_id`, whatever the state, including a
  FREEZE sent outside a shift (0 before the first arm; v1.3: the resumed
  value on a rig registered over a tombstone, §12.4). Read it from the Rig.
* **`round_id`** is `Board.round_id` at signing.
* **BREAK and FREEZE** bind the `reason` byte. FREEZE accepts any value (the app
  sends 3).

Secp256r1SigVerify instruction data, as `p256_introspect::client` builds it and
as `messages.json` shows:

```
num_signatures u8 | padding u8 |
num_signatures × { signature_offset u16, signature_instruction_index u16,
                   public_key_offset u16, public_key_instruction_index u16,
                   message_data_offset u16, message_data_size u16,
                   message_instruction_index u16 } |
per signature: public_key[33] | signature[64] | message[32]
```

One signature is 145 bytes (header `01003100ffff1000ffff71002000ffff`). At most
8 signatures fit per precompile instruction.

**Every** offsets record's three instruction indices must be `0xFFFF` or the
precompile's own top-level index. One foreign record fails the whole
instruction with `ForeignInstructionIndex` (0x25600007). The program checks the
instructions sysvar address (0x25600001 if it is wrong), the precompile program
id, bounds, low-S, the key and the message.

### 4.2 Registrar voucher (Ed25519, raw 111 bytes)

```
0 "HDreg"(5) | 5 program_id(32) | 37 authority(32) | 69 p256_pubkey(33) | 102 level u8 | 103 expiry_slot u64
```

The voucher is Ed25519 over the raw bytes (not SHA-256 first). It is carried by
an Ed25519SigVerify instruction in the same transaction, located by
`(ed25519_ix, ed25519_sig_index)` from the instruction data.

The registrar's format is 223 bytes with header
`01003000ffff1000ffff70006f00ffff`: pubkey at 16, signature at 48, message at
112, all indices 0xFFFF. `registrar.json` holds it, and it is accepted as-is.

The program requires:

* every offsets record points only into its own instruction;
* the verified pubkey equals `config.registrar`;
* the message equals the preimage rebuilt from (`crate::ID`, the **signing
  authority**, the p256 key in the instruction data, `level`, `expiry_slot`);
* `level` is 1 or 2 (**level 0 is refused**; register without an attestation
  instead);
* `expiry_slot > Clock.slot`;
* `expiry_slot - Clock.slot <= 25,920,000` (`MAX_ATTESTATION_TTL_SLOTS`, four
  times the registrar's default lifetime; §12.13).

Every failure is `InvalidAttestation` (21).

The **P-256 tail**, used by `arm_shift` / `break_shift` / `freeze_rig` in mode
1, is always `counter u64 | p256_ix u8 | p256_sig_index u8`: the counter
**first**.

`p256_ix` / `hb_ix` / `ed25519_ix` are the **absolute top-level** index of the
precompile instruction in the transaction (compute-budget instructions count).

On the P-256 path the wallet does not sign. The `authority` account must still
be passed, equal to `rig.authority`. The fee payer is **not** an instruction
account.

### 0 `initialize_config`

Accounts:

```
0 [s,w] upgrade authority (pays rent)
1 [w]   Config PDA
2 []    ProgramData
3 []    System
```

Data:

```
0 tag | 1 governance[32] | 33 registrar[32] | 65 crank_fee u64 | 73 executor_fee u64
      | 81 bury_bps u16 | 83 ore_layout_hash[32]
```

Checks:

* The signer must be the upgrade authority recorded in this program's
  ProgramData. An immutable program, a forged ProgramData or a stranger →
  `Unauthorized` (5).
* `crank_fee <= executor_fee` and `bury_bps <= 10,000` → else
  `InvalidInstruction` (0).
* `ore_layout_hash` must equal `sha256(LAYOUT_PREIMAGE)` → else
  `InvalidOreAccount` (3).
* Init-only: pre-funding the address is tolerated, re-initialization is not.

      [| 35 ed25519_ix u8 | 36 ed25519_sig_index u8 | 37 level u8 | 38 expiry_slot u64]
```

`has_attestation` must be 0 or 1: any other value is `InvalidInstruction`.
The key must start with `02` or `03`, otherwise `InvalidPublicKeyEncoding`
(0x2560000c). A Rig address that is not `["rig", signer]` →
`InvalidSeeds`. The voucher rules are in §4.2.

The handler:

* creates the Rig with state Idle, tier 0 and `freezes_left` 2;
* sets `week_start_ts = now`;
* caches the ORE Automation and Miner bumps;
* emits **RigRegistered**.

v1.3: if the Rig PDA holds a RigTombstone, the same instruction grows it back
into a Rig that resumes from the tombstone's `shift_id` and `hb_counter`
(§12.4). Nothing in the data or the account list changes.

### 2 `verify_seeker`

Accounts:

```
0 [s,w] authority
1 [w]   Rig (rig.authority == authority)
2 [w]   SeekerSeat PDA ["seeker", mint]
3 []    SGT token account (Token-2022)
4 []    SGT mint
5 []    System
6 [w]   previous rig (only when the seat points at another rig)
```

Data: `0 tag`.

* `sgt_verify::verify_sgt(token_account, mint, authority)` must pass. Its
  errors keep their `0x5347_00xx` codes.
* The seat is created, or re-pointed to this rig. `rig.tier = 1` and
  `rig.sgt_mint = mint`.
* If the seat points at another rig, that rig must be passed as account 6,
  otherwise `SeatTaken` (17). It is downgraded to tier 0 if it still claims
  this mint.
* A seat whose stored mint differs is `InvalidSgt` (16).
* Emits **SeekerVerified**.

### 3 `set_caps`

Accounts: `0 [s] authority | 1 [w] Rig`.

Data:

```
0 tag | 1 cap_week u64 | 9 cap_shift u64 | 17 cap_round u64 | 25 cap_max_cost u64
      | 33 caps_expiry_ts i64
```

This is wallet-only: the only instruction that can raise limits. It is valid in
any state. It clamps `plan_max_ev_cost ≤ cap_max_cost` and
`plan_dig_lamports ≤ cap_round`, and rolls the spend week. The caps are not
checked against each other.

### 4 `rotate_key`

Accounts:

```
0 [s] authority
1 [w] Rig
2 []  Config
3 []  Instructions sysvar (only with a voucher)
```

Data: the same as `register_rig`, with tag 4.

It replaces `p256_pubkey`. Without a voucher, `attestation_level` and
`attestation_expiry_slot` reset to 0. `hb_counter` is kept, so old signatures
stay stale. Valid in any state.

### 5 `arm_shift`

Accounts:

```
0 [w]    Rig
1 [s*]   authority (s* = must sign in mode 0; in mode 1 must equal rig.authority, no signature)
2 []     ORE Board
3 []     Instructions sysvar (mode 1 only)
```

Data:

```
0 tag | 1 mode u8 (0 wallet, 1 P-256) | 2 max_ev_cost u64 | 10 dig_lamports u64
      | 18 split u8 | 19 solo u8 | 20 lease u8 | 21 flags u8 | 22 window_start i64
      | 30 window_end i64
      [| 38 counter u64 | 46 p256_ix u8 | 47 p256_sig_index u8]
```

Checks, in order:

1. The Board is valid.
2. `authority == rig.authority` → else `Unauthorized`.
3. The state is Idle. Frozen → `RigFrozen` (14); any other state →
   `InvalidRigState` (24).
4. The plan fields:
   * `lease` in 1..=3, `split ≤ 15`, `solo ≤ 10`;
   * `flags` ⊆ {bit0, bit1};
   * unless focus-only: `split + solo ≥ 1` and `dig_lamports > 0`;
   * `window_start < window_end`.

   Any failure → `InvalidInstruction`. Also `now ≤ window_end`, else
   `OutsideWindow` (11).
5. `now ≤ caps_expiry_ts` → else `CapsExpired` (10).
6. `max_ev_cost ≤ cap_max_cost` and `dig_lamports ≤ cap_round` → else
   `PlanExceedsCaps` (15).
7. Authorization:
   * mode 0: the wallet signs;
   * mode 1: `counter > hb_counter` (else `StaleHeartbeat` (7)) and the PLAN
     verifies.

Effects:

* `shift_id += 1`, state = Armed, the plan is stored.
* The lease, gaps, `spent_shift`, dark rounds and rounds dug reset.
* `shift_start_round = Board.round_id`, `shift_open = 1`, `break_reason = 0`,
  `shift_start_ts = now`, and the week rolls.
* Emits **ShiftArmed**.

### 6 `dig` (§6)

Accounts, in fixed order:

```
 0 [s,w] cranker            4 [w] ORE Config     8 []  ORE program       12.. per rig i (4 each):
 1 []    Config             5 [w] ORE Round      9 [w] entropy Var            [w] rig
 2 [w]   Executor PDA       6 [w] ORE Treasury  10 []  entropy program        [w] authority (= rig.authority)
 3 [w]   ORE Board          7 []  System        11 []  Instructions sysvar    [w] ORE Automation ["automation", authority]
                                                                              [w] ORE Miner ["miner", authority]
```

Data: `0 tag | 1 n u8 (1..=32) | 2 + 20i: entry i`. Each entry is:

```
+0 hb_ix u8 (0xFF = reuse the current lease) | +1 hb_sig_index u8 | +2 counter u64
+10 round_id u64 | +18 lease_rounds u8 | +19 _pad u8 (not checked)
```

With `hb_ix = 0xFF`, the rest of the entry is ignored.

Exactly `12 + 4n` accounts, or `InvalidInstruction`. The Round must be
`["round", Board.round_id]` with a matching `id`. Always pass all 12 shared
accounts: ORE `deploy` does `split_at(10)`.

### 7 `record_heartbeats`

Accounts:

```
0 []  ORE Board
1 []  Instructions sysvar
2.. [w] rig_0 .. rig_{n-1}
```

Data: the same framing as `dig` (`n` 1..=32, 20-byte entries); exactly
`2 + n` accounts.

It verifies each HEARTBEAT exactly as `dig` does (§6.2) and updates the counter,
lease, dark rounds and gaps, with **no CPI**. It works while the Config is
paused. The rig address is bound by the signed preimage; its PDA derivation is
not re-checked.

For each rig:

* `hb_ix = 0xFF` → `InvalidHeartbeat` (6).
* State Armed, Down or Cooling → verify. Frozen → `RigFrozen`; any other state
  → `RigNotArmed` (13).
* Success emits **HeartbeatsRecorded**. A failure emits **RigSkipped**.
* A duplicate rig fails the transaction with `DuplicateRig` (22).

### 8 `break_shift` / 9 `freeze_rig`

Accounts:

```
0 [w]  Rig
1 [s*] authority (s* = signs in mode 0; in mode 1 must equal rig.authority)
2 []   Instructions sysvar (mode 1 only)
```

Data:

```
0 tag | 1 mode u8 | 2 reason u8 [| 3 counter u64 | 11 p256_ix u8 | 12 p256_sig_index u8]
```

**BREAK:**

* The reason must be one of 1, 2, 4, 5, 6, 7 or 8, otherwise
  `InvalidInstruction`. This is checked before the state.
* It is allowed from Armed, Down or Cooling. From Frozen → `RigFrozen`; from
  Idle or Broken → `InvalidRigState`.
* Reasons 1, 2 and 7 → **Cooling**. Reasons 4, 5, 6 and 8 → **Broken**.
* It stores `break_reason` and emits **ShiftBroken**.

**FREEZE:**

* It is allowed from any state. Freezing a frozen rig is idempotent (a P-256
  FREEZE still consumes its counter).
* If it interrupts an open shift (the rig was not already Frozen and
  `shift_open == 1`), it stores `break_reason = 3` and emits
  **ShiftBroken(3)**.
* On the wallet path the reason byte is ignored.

### 10 `unfreeze_rig`

Accounts: `0 [w] Rig | 1 [s] authority`. Data: `0 tag`.

The rig must be Frozen, otherwise `InvalidRigState`. It goes Frozen → Idle, or
Frozen → **Broken** if a shift is still open, so that `end_shift` can seal that
shift with reason `freeze`.

### 11 `end_shift`

Accounts:

```
0 [s,w] caller (pays the ShiftLog rent)
1 [w]   Rig
2 [w]   ShiftLog PDA ["shift", rig, rig.shift_id]
3 []    ORE Board
4 []    System
```

Data: `0 tag`.

* It requires `shift_open == 1`, otherwise `InvalidRigState`.
* The authority may end the shift at any time. Anyone else needs
  `now > plan_window_end_ts` **and** `lease_to_round + 3 < Board.round_id`
  (the lease expired more than `PERMISSIONLESS_END_GRACE_ROUNDS` = 3 rounds
  ago; §12.13), otherwise `Unauthorized`.
* A wrong ShiftLog address → `InvalidSeeds`.
* The handler writes the ShiftLog (§6.8), does the streak accounting, sets
  `shift_open = 0`, and sets the state to Idle (a Frozen rig stays Frozen).
* It emits **ShiftEnded**, then **ShiftEndedV2**.
* v1.3: the log records the first 16 bytes of the caller's address
  (`payer_prefix`), which `close_shift_log` later refunds (§12.5).

### 12 `propose_config`

Accounts: `0 [s] governance | 1 [w] Config`.

Data:

```
0 tag | 1 registrar[32] | 33 crank_fee u64 | 41 bury_bps u16 | 43 paused u8 (0/1)
```

* It sets `pending_*` with `pending_eta_slot = slot + 864,000` and, since
  v1.3, `pending_eta_ts = unix_timestamp + 259,200` (§12.3). A new proposal
  replaces the pending one and restarts the clock.
* `paused = 1` also sets `config.paused = 1` **immediately** (§6.6).
* `executor_fee` cannot be changed.

### 13 `apply_config`

Accounts: `0 [w] Config`. Data: `0 tag`.

It requires `pending_exists`, otherwise `InvalidInstruction`, and
`slot >= pending_eta_slot`, otherwise `TimelockNotElapsed` (19). Since v1.3 it
also requires `unix_timestamp >= pending_eta_ts` (the same error; §12.3). It
applies the registrar, `crank_fee`, `bury_bps` and `paused` together, then
clears the pending fields.

### 14 `close_rig`

Accounts:

```
0 [s,w] authority (receives the rent)
1 [w]   Rig
2 [w]   SeekerSeat ["seeker", rig.sgt_mint] (required when tier == 1)
```

Data: `0 tag`.

* The state must be Idle or Frozen, otherwise `InvalidRigState`.
* For tier 1: a missing seat → `NotEnoughAccountKeys`; a wrong seat address →
  `InvalidSgt`. The seat is closed only if it still points at this rig.
* Every lamport goes to the stored authority, and the account returns to
  System.
* Emits **RigClosed**.

v1.3: that is still exactly what happens to the seat, and to a rig that never
armed a shift and never accepted a P-256 message. Any other rig is shrunk to a
32-byte RigTombstone at the same address; the authority receives every lamport
above the tombstone's rent (§12.4). Same data, same accounts, same event.

## 6. Semantics

### 6.1 `dig`: transaction-level checks (a failure fails the whole transaction)

1. `n` and the data length. Exactly `12 + 4n` accounts. The cranker signs and
   is writable.
2. The Config is the canonical PDA and initialized (else `InvalidAccountTag`).
   `paused == 0`, otherwise **`Paused` (18)**.
3. Executor account checks, otherwise `InvalidExecutor` (2):
   * the address is the Executor PDA;
   * it is System-owned, data-less and writable.
4. ORE account checks, otherwise `InvalidOreAccount` (3):
   * the Board, ORE Config and Treasury pass the address, owner, length and
     discriminator checks;
   * `Board.production_cost_ema != 0`;
   * `end_slot > start_slot`, or `end_slot == u64::MAX`;
   * the Round is `PDA(Board.round_id)` with a matching id;
   * the System, ORE, Var and entropy-program slots are the pinned addresses.
5. The Board, ORE Config, Round, Treasury and Var are writable.
6. The instructions sysvar address is correct.
7. No rig appears twice (`DuplicateRig`).
8. Per rig, before any skip decision:
   * the rig account is valid. An account that is not program-owned with a
     Rig's length (the tombstone or the empty PDA a `close_rig` leaves) is the
     one exception: it is **skipped** with `InvalidAccountTag` (4), so a rig
     closed after the batch was planned does not fail the others (§12.13);
   * `authority == rig.authority` (else `Unauthorized`);
   * the Automation and Miner equal the PDAs re-derived from `rig.authority`
     with the cached bumps (else `InvalidOreAccount`);
   * the authority, Automation and Miner are writable;
   * if the Automation exists, `automation.authority == rig.authority` (else
     `InvalidOreAccount`).

### 6.2 `dig`: per rig, in order. Any failure **skips** the rig with `RigSkipped{rig, round_id, error}`

| Step | Condition | Skip code |
|---|---|---|
| 0 | the rig account is not program-owned with a Rig's length (closed: a tombstone or nothing) | 4 InvalidAccountTag |
| 1 | Automation closed or revoked (not an ORE Automation) | 2 InvalidExecutor |
| 1 | `automation.executor != Executor PDA` | 2 InvalidExecutor |
| 1 | `automation.strategy != 2` or `automation.fee != config.executor_fee` (including 0) | 23 StrategyMismatch |
| 1 | Miner missing, or `miner.authority != rig.authority` | 3 InvalidOreAccount |
| 2 | State Frozen | 14 RigFrozen |
| 2 | State Idle or Broken, or Cooling with `hb_ix = 0xFF` | 13 RigNotArmed |
| 3 | Heartbeat (when `hb_ix != 0xFF`): `round_id > Board.round_id` or `lease_rounds == 0` | 6 InvalidHeartbeat |
| 3 | `counter <= rig.hb_counter` | 7 StaleHeartbeat |
| 3 | Precompile introspection: wrong key, wrong message (for example a wrong `shift_id` or round), foreign offsets, high-S, bad indices | `0x2560_00xx` (§8) |
| 4 | No lease covers `Board.round_id` (`lease_to == 0`, or the round is outside `[lease_from, lease_to]`) | 8 LeaseExpired |
| 5 | `last_dug_round == Board.round_id` | 9 AlreadyDugRound |
| 6 | `now > caps_expiry_ts` | 10 CapsExpired |
| 6 | `now < plan_window_start_ts` or `now > plan_window_end_ts` | 11 OutsideWindow |
| 6 | `plan_flags` has `FOCUS_ONLY` | 30 FocusOnly |
| 6 | Gate closed: `ema_ev > min(plan_max_ev_cost, cap_max_cost)` | 1 CostGate |
| 7 | `per_tile == 0` (§6.4) | 12 BudgetExhausted |
| 7 | `automation.balance < per_tile·k + fee_due` | 28 InsufficientAutomationBalance |
| 8 | ORE pre-flight: `!(board.start_slot <= slot < board.end_slot)` (Board re-read) | 25 RoundNotActive |
| 8 | ORE pre-flight: `miner.round_id != Board.round_id && miner.checkpoint_id != miner.round_id` | 26 MinerNotCheckpointed |
| 8 | ORE pre-flight: `pot > max_motherlode·10^11` or `pot < min_motherlode·10^11` | 27 MotherlodeCondition |
| 8 | ORE pre-flight: `miner.checkpoint_fee == 0` and `executor.lamports < rent(0) + 10,000` | 31 ExecutorUnderfunded |
| 9 | Post-CPI: ORE returned Ok but no SOL landed on a square | 29 OreNoOp |

Two rules apply across these steps:

* A heartbeat that verifies is **consumed**: its counter and lease persist, and
  Armed or Cooling becomes Down, even if a later step skips the rig.
* A builtin `ProgramError` inside a skip maps to `u32::MAX - k`. This should
  not happen in practice.

### 6.3 Leases and dark rounds

* A heartbeat grants `[round_id, round_id + min(lease_rounds, plan_lease_rounds) − 1]`.
  The preimage binds the signed `lease_rounds`.
* **Leases only move forward.** A verified heartbeat whose lease ends at or
  before the current `lease_to_round` consumes its counter but changes nothing.
  `lease_to_round == 0` means no lease in this shift, and `arm_shift` resets it.
* **Dark rounds** are the rounds a new lease newly covers, counted from
  `shift_start_round`. Skipped-over rounds add to `gap_count`.
* **At `end_shift`:**

  ```
  dark_rounds -= max(0, lease_to - end_round)
  gaps        += end_round - max(lease_to, shift_start_round - 1)
  ```

### 6.4 The gate, the dig budget, and the fee inside the caps

* **The gate** is computed once per transaction, in u128:
  `ema_ev = ema · 6 · 500 · 10^11 / (5 · (500 · 10^11 + pot))`.
  * `ema = Board.production_cost_ema` (lamports per ORE).
  * `pot = Treasury.motherlode` (ORE base units, 10^11 per ORE).
  * The rig digs iff `ema_ev <= min(plan_max_ev_cost, cap_max_cost)`, an
    **inclusive** comparison.
  * `RigDug.ema_ev` saturates at u64::MAX.
* **Squares.**
  * Squares the Miner already holds this round (`miner.round_id ==
    Board.round_id`) are excluded, because ORE would skip them.
  * From the rest, the program takes the `plan_split_tiles` least-crowded
    split squares and the `plan_solo_tiles` least-crowded solo squares. The
    order is by `Round.deployed`, ties to the lowest index, and "solo" is ORE's
    keccak `distribution_mask(round_id)`.
  * `k = popcount(mask)`: the squares actually chosen, which can be fewer than
    `split + solo`.
* **The fee is reserved inside every cap.**

  ```
  budget   = min(plan_dig_lamports,
                 min(cap_round, cap_shift − spent_shift, cap_week − spent_week) − automation.fee)   (saturating)
  per_tile = min(budget / k, automation.amount)
  fee_due  = automation.fee if the Miner has no deployment this round, else 0
  ```

  The CPI is ORE `deploy(per_tile, mask)`. For example, with
  `cap_round = plan_dig = 1,000,000` on 10 squares, the program deploys
  99,500 per square (995,000 in total) and the whole debit is 1,000,000.
* **Post-CPI accounting.** A violation fails the transaction.
  * `debit` = the Automation balance delta. If ORE closed the Automation,
    `debit` = SOL on squares + the fee received.
  * The debit must equal the squares plus the fee the Executor received,
    otherwise `InvalidOreAccount`.
  * The spend is checked again: `debit <= cap_round`,
    `spent_shift + debit <= cap_shift` and `spent_week + debit <= cap_week`,
    otherwise **`BudgetExhausted` fails the transaction**.
  * `spent_*` count the whole debit.
* **Events and logs.** `RigDug.lamports` = the SOL placed on squares, with no
  fee. `ShiftEnded.lamports` and `ShiftLog.lamports_deployed` = `spent_shift`,
  which includes the fees.

### 6.5 The Executor and the crank reimbursement

* **The Executor invariant.** A violation fails the transaction with
  `InvalidExecutor`.
  * `executor_after + CHECKPOINT_FEE (10,000) >= executor_before`.
  * `executor_after >= executor_before` when the Miner still had its checkpoint
    reserve.
  * The Executor stays System-owned and data-less.
* **The reimbursement** (`config.crank_fee` to the cranker) is paid only
  after a real deploy **that brought the Executor at least `crank_fee` in this
  same dig** (`fee_received >= crank_fee`, §12.13), only when `crank_fee > 0`
  and the cranker is not the Executor, and only if the Executor holds at least
  `rent_exempt(0) + EXECUTOR_RESERVE (100,000) + crank_fee` before the
  transfer. It therefore keeps at least `rent_exempt(0) + 100,000` for later
  `CHECKPOINT_FEE` top-ups. Otherwise it is silently skipped and the dig still
  counts.
* ORE charges the Automation fee on a Miner's first deploy of a round only. A
  rig whose Miner already deployed this round (its owner deployed by hand) is
  dug without a fee and without a reimbursement; a crank may skip it.
* An ORE no-op (29) has no reimbursement and moves no dig counters, but its
  debit, if any, is counted.

### 6.6 Pause semantics

* `Config.paused == 1` makes **`dig` fail the whole transaction** with
  `Paused` (18) before any rig is processed.
* Nothing else is paused, so users can always exit. These keep working:
  `record_heartbeats`, `arm_shift`, `break_shift`, `freeze_rig`,
  `unfreeze_rig`, `end_shift`, `set_caps`, `rotate_key`, `register_rig`,
  `verify_seeker` and `close_rig`.
* `propose_config` with `paused = 1` pauses **immediately**. Un-pausing, and
  every other change, waits for `apply_config` after the timelock: 864,000
  slots and, since v1.3, 72 hours of cluster time, whichever ends later
  (§12.3).

### 6.7 State machine (Cooling / Broken)

```
Idle ──arm_shift──▶ Armed ──fresh heartbeat (dig / record_heartbeats)──▶ Down
Armed / Down / Cooling ──BREAK 1 pickup, 2 screen_on, 7 unplugged──▶ Cooling
Cooling ──fresh heartbeat (counter > the BREAK's; dig or record_heartbeats)──▶ Down
Armed / Down / Cooling ──BREAK 4 lease_lapse, 5 budget, 6 manual, 8 unlocked──▶ Broken
any ──FREEZE──▶ Frozen            (records break_reason 3 if a shift was open)
Frozen ──unfreeze_rig (wallet)──▶ Idle (no open shift) | Broken (shift open)
Armed / Down / Cooling / Broken / Frozen-with-shift ──end_shift──▶ Idle (Frozen stays Frozen)
```

* **Only Armed and Down dig.** Cooling digs only with a fresh heartbeat in the
  same entry: reusing a lease while Cooling is refused.
* **Broken** does nothing until `end_shift`.
* **`arm_shift`** requires Idle.
* **`close_rig`** requires Idle or Frozen.

### 6.8 `end_shift`: reason, mode and streak

* **Reason.**
  * Cooling or Broken → the stored `break_reason`.
  * Frozen → 3 `freeze`.
  * Armed or Down, in this order:
    * no dark round → 4 `lease_lapse`;
    * the authority ends it inside the window → 6 `manual`;
    * otherwise → 0 `completed`.
* **Mode.** Focus-only → 2; otherwise `DAY` → 1; otherwise 0.
* **Streak.** A shift qualifies iff `reason == completed` and
  `dark_rounds >= 1`. Days are UTC unix days of `end_ts`. `freezes_left`
  refills to 2 whenever `day / 30` changes. For a qualifying shift:
  * next day → +1;
  * `m` missed days with `m <= freezes_left` → +1 and `freezes_left -= m`;
  * the same day → unchanged;
  * otherwise → the streak restarts at 1.

  A non-qualifying shift neither extends nor breaks the streak.

## 7. Events (`sol_log_data`, one slice, byte 0 = tag)

A tag's length **never** changes: consumers decode by exact length, so new
fields always get a new tag. Only `Program data:` lines emitted while
heads_down is the innermost executing program are heads_down events.

| Tag | Event | Layout (offset: field) | Length | Emitted by |
|---|---|---|---|---|
| 1 | RigDug | `1 rig · 33 round_id u64 · 41 lamports u64 (on squares) · 49 mask u32 · 53 ema_ev u64` | 61 | `dig` |
| 2 | RigSkipped | `1 rig · 33 round_id u64 · 41 error u32` | 45 | `dig`, `record_heartbeats` |
| 3 | ShiftArmed | `1 rig · 33 shift_id u64` | 41 | `arm_shift` |
| 4 | ShiftEnded | `1 rig · 33 shift_id u64 · 41 dark_rounds u64 · 49 rounds_dug u64 · 57 lamports u64 · 65 reason u8` | 66 | `end_shift` (first) |
| 5 | SeekerVerified | `1 rig · 33 sgt_mint · 65 member_number u64` | 73 | `verify_seeker` |
| 6 | RigRegistered | `1 rig · 33 authority · 65 tier u8 · 66 attestation_level u8` | 67 | `register_rig` |
| 7 | RigClosed | `1 rig` | 33 | `close_rig` |
| 8 | HeartbeatsRecorded | `1 rig · 33 round_id u64 (= Board.round_id) · 41 dark_rounds_added u64` | 49 | `record_heartbeats` (one per accepted rig) |
| 9 | ShiftBroken | `1 rig · 33 shift_id u64 · 41 reason u8` | 42 | `break_shift`; `freeze_rig` when it interrupts an open shift (reason 3) |
| 10 | ShiftEndedV2 | tag 4's fields, then `66 start_round u64 · 74 end_round u64 · 82 mode u8` | 83 | `end_shift` (second) |

Notes on each field:

* **`round_id` in RigDug, RigSkipped and HeartbeatsRecorded** is the live
  `Board.round_id`.
* **`RigDug.mask`** is the mask passed to ORE. Squares the Miner already held
  were excluded, so the mask requested equals the squares credited.
* **ShiftEnded and ShiftEndedV2.** A consumer that decodes tag 10 should
  ignore tag 4 in the same instruction. Tag 4 is kept for v1 decoders.

## 9. Measured transaction limits (live ORE fork, `tests/tests/capacity.rs`)

Each rig in a `dig` adds 4 account keys, a 20-byte entry and a 143-byte
secp256r1 entry. The secp256r1 entry is 14 bytes of offsets, a 33-byte key, a
64-byte signature and a 32-byte digest.

| Format | Max rigs per `dig` transaction | What binds |
|---|---|---|
| legacy / v0 without a lookup table | **2** | 1,232-byte packet |
| v0 + one address lookup table | **5** | 1,232-byte packet |
| v1 (4,096 B, no lookup tables, ≤ 64 addresses) | **11** | 4,096 bytes; the address cap `14 + 4n` would bind at 13 |

* **Compute.** About 36k to 43k CU per rig, median over fresh forks. About
  22k to 26k of it is ORE `deploy`, which varies with the live round and with
  ORE's bump search on each wallet's PDAs. So 11 rigs use 27% to 29% of 1.4M
  CU (372,109 and 398,785 CU in two runs).
* **Fees.** Each secp256r1 signature adds a 5,000-lamport fee, and `crank_fee`
  must cover it.
* **Batch cap.** At most 32 rigs per instruction.

## 10. Not implemented in v1.1 (open)

Three of these were closed in v1.3; the text is kept for the record.

* The P-256 key-uniqueness marker (THREAT_MODEL §6.8). **v1.3: decided
  against, §12.7.**
* ORE's ProgramData version pin (docs/ORE.md drops it for an immutable v1).
* `bury_bps` is stored but unused: the Executor's SOL surplus is not routed
  to Bury. (The v1.2 Bury auction, §11.8, sells SKR forfeits only.)
* Closing ShiftLogs after 30 days. Because ShiftLogs are never closed, a rig
  that is closed and re-registered restarts at `shift_id` 1, and `end_shift`
  of a shift whose `["shift", rig, id]` log already exists fails. v1.2 Focus
  Bonds guard against this (§11.6). **v1.3: fixed. A re-registered rig
  resumes its `shift_id` (§12.4), and `close_shift_log` returns the rent
  (§12.5).**
* `attestation_expiry_slot` is re-checked only where v1.2 needs it
  (`join_stack` at attested-only tables). **v1.3: also at every check-in of
  an attested-only table, the only other place the program relies on it
  (§12.6).**
* A heartbeat applied inside `dig` emits no `HeartbeatsRecorded`. Its evidence
  is `RigDug` or `RigSkipped`, and the totals are in `ShiftEnded` /
  `ShiftEndedV2`.

## 11. v1.2 (additive): SKR — Stack, Focus Bond, Gift a Rig, Bury auction

Everything in this section is **added** to v1.1. It reuses the v1.1
conventions (little-endian, lengths include the tag, exact data lengths,
owner + length + tag + version checks before any read, canonical bumps stored
in the header, init-only creation that tolerates pre-funding, closes that zero
the data and pay the stored recipient).

SKR is used here only as **collateral, bond and gift currency**. Nothing below
mints SKR, pays a return for holding it, or touches Solana Mobile's SKR
staking program. Every SKR that leaves a vault goes back to the wallet that
put it there, to a finisher at the same table (out of other players'
forfeits), or into the Bury auction, where it is sold for ORE that ORE's own
`bury` instruction burns (90%) and distributes to ORE's stake program (10%).

### 11.2 PDAs and vaults

| Account | Seeds | Notes |
|---|---|---|
| StackTable | `["stack", host, table_id u64 LE]` | the host is in the seeds, so nobody can squat a table id |
| StackSeat | `["stackseat", table, key]` | `key` = the rig's SGT mint at **remote** tables (one seat per Seeker), the **rig** address at in-person tables (one seat per rig) |

| GiftEscrow | `["gift", sender, nonce u64 LE]` | the sender is in the seeds (no squatting); the recipient is stored |

Seed prefixes are distinct per purpose (audit class 8); `stack` and `shift`
seeds have equal length but differ in their bytes.

**Vaults** are the canonical SPL Token ATAs of their PDA:
`ATA(owner, mint) = find_program_address([owner, SPL Token, mint], ATA program)`.

| Vault | Owner | Mint | Created by |
|---|---|---|---|
| table vault | StackTable | SKR | the client (ATA `CreateIdempotent`) before `open_stack` |
| bond vault | FocusBond | SKR | the client before `lock_focus_bond` |
| Bury SKR vault (the lot) | BuryVault | SKR | anyone, after `init_bury_vault` |
| Bury ORE vault (the `bury` sender) | BuryVault | ORE | anyone, after `init_bury_vault` |

A vault is checked at creation (derived address) and then compared with the
address stored in its PDA: owner SPL Token, mint, owner field == the PDA, no
delegate, no close authority. Only that PDA can move tokens out, and it signs
only transfers to recipients fixed by state. Tokens sent to a vault outside
the program (donations) are never counted as bonds; a Focus Bond's donations
follow the bond's fate, a table's stay in its vault.

These seeds deviate from the SPEC draft (`["stack", table_id]`,
`["stackseat", table, sgt_mint]`, `["bond", sgt_mint, shift_id]`,
`["gift", recipient_sgt_mint, nonce]`): guests have no SGT, and keying by the
creator prevents squatting.

#### 15 `open_stack`

```
0 [s,w] host (pays the table rent)
1 [w]   StackTable PDA ["stack", host, table_id]
2 []    table SKR vault = ATA(table, SKR)   (created earlier in the transaction)
3 []    ORE Board
4 []    System
```

Data: `0 tag | 1 table_id u64 | 9 bond u64 | 17 start_round u64 | 25 end_round u64 | 33 grace_gaps u32 | 37 flags u8 | 38 max_seats u8`.

Checks, in order:

* the host signs;
* `flags` ⊆ {bit0, bit1, bit2} and `max_seats` in 2..=8, else
  `InvalidStackParams` (34);
* `bond` in 1..=cap (cap 2,000 SKR; remote 1,000 SKR), else
  `AmountOutOfRange` (33);
* with `len = end − start + 1`: `start > Board.round_id`, `end ≥ start`,
  `start − Board.round_id ≤ 10,080`, `len ≤ 1,440`, `grace_gaps < len`, else
  `InvalidStackParams`;
* the canonical table address (`InvalidSeeds`), then the vault (§11.2).

`REMOTE` sets `ATTESTED_ONLY`. Emits **StackOpened**.

#### 16 `join_stack`

```
0 [s,w] authority (= rig.authority; pays the seat rent; signs the bond transfer)
1 []    Rig
2 [w]   StackTable
3 [w]   StackSeat PDA ["stackseat", table, key]
4 [w]   authority's SKR token account (source; owner field = authority)
5 [w]   table SKR vault
6 []    ORE Board
7 []    SPL Token
8 []    System
9 []    SGT token account (Token-2022)   } only when the table needs a verified
10 []   SGT mint                          } Seeker (remote, or bond > 500 SKR)
```

Data: `0 tag`.

Checks:

* the authority signs and is `rig.authority` (`Unauthorized`);
* the table is Open, `Board.round_id < start_round` and the table is not
  full, else `StackJoinClosed` (35);
* `ATTESTED_ONLY` needs `attestation_level ≥ 1` and
  `attestation_expiry_slot > Clock.slot` (v1.3: and again at every check-in,
  §12.6);
* when a verified Seeker is needed: `rig.tier == 1` and
  `sgt_verify::verify_sgt(account 9, account 10, authority)` with
  `mint == rig.sgt_mint`, re-verified now (a stale tier is never trusted).
  Eligibility failures are `StackIneligible` (36); SGT failures keep their
  `0x5347_00xx` codes;
* the seat address must be canonical for the key (`InvalidSeeds`); a second
  seat for the same key fails at creation (`AccountAlreadyInitialized`).

Then an SPL Token `Transfer(bond)` from the source to the vault, authorized by
the signer, and the vault balance is re-read (`+bond` exactly). Emits
**StackJoined**.

#### 17 `stack_checkin`

```
0 []  ORE Board
1 []  Instructions sysvar
2 []  StackTable
then, per entry i: [w] StackSeat_i, [w] Rig_i
```

Data: `0 tag | 1 n u8 (1..=8) | 2 + 20i: entry i`, the `dig` entry (§5, tag 6).

* `hb_ix = 0xFF` is **observe mode**: count the lease a `dig` or
  `record_heartbeats` already applied in this round.
* Otherwise **verify mode**: the entry's HEARTBEAT is verified and applied
  here, exactly as `record_heartbeats` does.

Exactly `3 + 2n` accounts. These fail the transaction: the table is not Open,
or `Board.round_id` is outside `[start_round, end_round]`
(`InvalidStackState`, 38); a seat whose `table` or `rig` does not match
(`StackSeatMismatch`, 39); a seat or rig twice (`DuplicateRig`, 22); a seat or
rig passed read-only (`InvalidAccountData`). Per seat the rule of §11.5 runs,
and one **StackCheckin** event carries its result, so one seat (say, one whose
wallet closed its rig) never sinks the batch; a heartbeat verified here also
emits **HeartbeatsRecorded** (tag 8, v1.1 bytes).

#### 18 `settle_stack`

```
0 [w] StackTable
1 []  ORE Board
2 [w] table SKR vault
3 [w] BuryVault
4 [w] BuryVault SKR ATA
5 []  SPL Token
then [w] every StackSeat of the table, each once, any order
```

Data: `0 tag`.

* The table must be Open (`InvalidStackState`) and `Board.round_id >
  end_round` (`StackNotEnded`, 37).
* The seats must be exactly `seat_count` distinct seats of this table whose
  bonds add up to `total_bonds` (`StackSeatMismatch`).
* It writes each seat's outcome and payout (§11.5) and marks the table
  Settled.
* If `bury_amount > 0` it moves that SKR from the table vault to the Bury SKR
  vault (signed by the table PDA) and adds it to the lot. Accounts 3 and 4 are
  read only then.

Emits **BuryLotAdded** (when something goes to Bury), then **StackSettled**.

#### 19 `claim_stack`

```
0 [w] StackTable
1 [w] StackSeat (closed)
2 [w] seat authority (receives the seat rent; = seat.authority)
3 [w] seat authority's SKR token account (owner field = seat.authority)
4 [w] table SKR vault
5 []  SPL Token
```

Data: `0 tag`.

* Settled: pays `seat.payout` (kind 0).
* Open past `refund_after_ts`: the table becomes Refunding. Refunding pays
  `seat.bond` (kind 1).
* Open before then: `InvalidStackState`.

Account 2 must be the seat's authority (`Unauthorized`); account 3 is read
only when something is paid. The vault balance is re-read (`−amount`
exactly), `claimed_total` may never exceed `payouts_total` (Settled) or
`total_bonds` (Refunding), and the seat is closed, so a second claim fails
its account check (`InvalidAccountTag`). Emits **StackClaimed**.

#### 20 `lock_focus_bond`

```
0 [s,w] authority (= rig.authority; pays the bond rent; signs the transfer)
1 []    Rig
2 [w]   FocusBond PDA ["bond", rig, shift_id]
3 [w]   authority's SKR token account (source)
4 [w]   bond SKR vault = ATA(bond, SKR)   (created earlier in the transaction)
5 []    ShiftLog PDA ["shift", rig, shift_id]   (must not exist)
6 []    SPL Token
7 []    System
```

Data: `0 tag | 1 shift_id u64 | 9 amount u64`.

* `amount` in 1..=5,000 SKR (`AmountOutOfRange`).
* The rig's shift `shift_id` must be open and clean: `shift_open == 1`,

#### 21 `release_focus_bond`

```
0 [w] FocusBond (closed)
1 []  ShiftLog of the bonded shift
2 [w] bond SKR vault (emptied, closed)
3 [w] owner's SKR token account (owner field = bond.authority)
4 [w] bond authority (receives both rents)
5 []  SPL Token
```

Data: `0 tag`.

The ShiftLog must be the bonded shift's (same rig, `shift_id`, `start_round`,
`start_ts`) and sealed `completed` (0), else `BondNotResolvable`; before the
shift is sealed the log does not exist (`InvalidAccountTag`). The whole vault

#### 22 `forfeit_focus_bond`

```
0 [w] FocusBond (closed)
1 []  ShiftLog PDA ["shift", bond.rig, bond.shift_id]   (sealed, or empty)
2 []  bond.rig (read only when the log is empty; may be closed)
3 [w] bond SKR vault (emptied, closed)
4 [w] BuryVault
5 [w] BuryVault SKR ATA
6 [w] bond authority (receives both rents)
7 []  SPL Token
```

Data: `0 tag`. Accounts 1 and 2 must be the canonical log address and the
bond's rig (`InvalidSeeds`). It is forfeitable when:

* the log is the bonded shift's and sealed with any reason but `completed`
  (`FocusBondForfeited.reason` = that reason); or
* the bonded shift can never be sealed: the log slot holds another shift's
  log, or it is empty and the rig no longer has the bonded shift open (it was
  closed, and maybe re-registered). That is reason 255 `abandoned`.

A completed log, or an empty log while the rig still has the bonded shift
open, is `BondNotResolvable`. The whole vault balance goes to the Bury lot;
the vault ATA and the bond close, and both rents go to the authority (they
were the owner's SOL). Emits **BuryLotAdded** (if any SKR moved), then
**FocusBondForfeited**.

#### 23 `create_gift`

```
0 [s,w] sender (pays the rent and the gift)
1 [w]   GiftEscrow PDA ["gift", sender, nonce]
2 []    System
```

Data: `0 tag | 1 nonce u64 | 9 recipient_kind u8 (0 wallet, 1 SGT mint) | 10 recipient [32] | 42 lamports u64`.

* `recipient_kind` ∈ {0, 1} and `recipient ≠ 0`, else `InvalidInstruction`.
* `lamports` in 1..=10 SOL, else `AmountOutOfRange`.
* The escrow is created (pre-funding tolerated), `lamports` are transferred
  into it from the sender, and `expiry_ts = now + 30 days`.

Emits **GiftCreated**.

The program escrows **lamports only**. A sender paying in SKR puts a Jupiter
SKR→SOL swap in the same transaction as a separate, sender-signed top-level
instruction; heads_down never CPIs Jupiter.

#### 24 `claim_gift`

```

#### 27 `bury_auction_buy`

```

Checks:

* the buyer signs;
* SPL Token, the ORE program, the Board and the Treasury are the pinned
  addresses (`InvalidOreAccount` for ORE's), and the BuryVault is canonical;
* `skr_amount > 0` (`AmountOutOfRange`) and `≤ lot_skr` (`AuctionEmpty`, 46);
* `cost = ceil(skr_amount · price / 10⁶)` (§11.8) must be `≤ max_ore`
  (`PriceAboveMax`, 47);
* the buyer's ORE and SKR accounts have the buyer as owner field, and both
  vaults match the BuryVault.

Then:

1. SPL Token `Transfer(cost)` of ORE from the buyer to the BuryVault ORE ATA;
   re-read (`+cost`).
2. Read the ORE mint supply. CPI ORE `bury(cost)` with the 12 accounts of
   `bury.rs:13-16`, signed by the BuryVault PDA.
3. Re-read: the ORE vault is back to its balance before step 1, and the ORE
   supply fell by exactly `cost − cost/10`. Otherwise `BuryMismatch` (48),
   and the whole transaction reverts.
4. SPL Token `Transfer(skr_amount)` of SKR from the lot to the buyer, signed
   by the BuryVault PDA; re-read.

Emits **BuryAuctionSold**.

### 11.5 Stack: the finish rule, and the Rig fields that prove it

A seat counts round `r = Board.round_id` only through `stack_checkin` during
round `r`. Per seat, in order (the first row that applies is the result):

| # | Condition | Result | Effect on the seat |
|---|---|---|---|
| 1 | the rig account is no longer a Rig (its wallet closed it) | 13 RigNotArmed | none |
| 2 | `seat.broken == 1` | 42 StackSeatBroken | none |
| 3 | seat bound and `rig.shift_id ≠ seat.shift_id` | 40 StackShiftMismatch | none |
| 4 | `rig.shift_open ≠ 1` | 13 RigNotArmed | none |
| 5a | `rig.break_reason ≠ 0` or state ∉ {Armed, Down}, seat **unbound** | 24 InvalidRigState | none: end that shift and arm a fresh one |
| 5b | the same, seat **bound** | 42 StackSeatBroken | `broken = 1`, for good |
| 6 | `rig.plan_lease_rounds ≠ 1` | 41 StackLeaseTooLong | none (the heartbeat is not consumed) |
| 7 | verify mode: the HEARTBEAT fails (§6.2 step 3, §6.3) | its code (6, 7, `0x2560_00xx`) | none |
| 8 | not `lease_from_round == lease_to_round == r` | 8 LeaseExpired | none |
| 9 | otherwise | 0 | bind to `rig.shift_id` if unbound; if `last_round < r`: `checked_rounds += 1`, `last_round = r` |

v1.3 adds one rule between rows 6 and 7, at attested-only tables only: the
rig's attestation must be live, else the result is 36 StackIneligible with no
effect on the seat (§12.6).

**The Rig fields that prove it.** These are all v1.1 fields, read only. Stack
adds no per-round state to the Rig and changes no Rig layout.

* `shift_id` (offset 200): the seat binds to it at its first counted round,
  and every later check-in requires the same shift.
* `shift_open` (336) and `state` (75): an open shift in Armed or Down.
* `break_reason` (337): 0 from `arm_shift`. Every BREAK (1, 2, 4, 5, 6, 7, 8)
  and every shift-interrupting FREEZE (3) sets it non-zero, and only the next
  `arm_shift` resets it. So it is **monotone within a shift**: a clean
  check-in at round `r` proves no BREAK or FREEZE happened in the bound shift
  up to `r`. Soft breaks count too: at a table a pickup is a flinch, even if
  the phone goes back down.
* `plan_lease_rounds` (178) == 1: every lease covers exactly its heartbeat's
  round.
* `lease_from_round` (216) == `lease_to_round` (224) == `Board.round_id`: a
  heartbeat for round `r` was applied. A heartbeat can never be for a future
  round and leases only move forward, so it was applied **during** round `r`.

**Finish rule** (at `settle_stack`). A seat finishes iff

```
broken == 0  and  last_round == end_round  and  (end − start + 1) − checked_rounds ≤ grace_gaps
```

That is: not broken in its shift, a lease covering `end_round` landed in
`end_round`, and the gaps are within grace.

**Payouts.** `B = Σ bond`, `W = Σ bond of finishers`, `F = B − W`,
`bps = 8,000` (0 at `BURY_ONLY` tables):

* finisher `i`: `bond_i + floor(F · bps · bond_i / (10⁴ · W))` (u128);
* everyone else: 0;
* Bury: `B − Σ payouts`, which is 20% of `F` plus rounding dust (all of `B`
  if `W == 0`, all of `F` at bury-only tables).

`Σ payouts + bury == B` always (exhaustively unit-tested for every finisher
subset of 1 to 8 seats), and each seat claims once.

**Timeout refund.** `refund_after_ts = opened_ts + (end_round −
opened_round + 1) · 120 + 259,200`: a pessimistic 120 s per round, plus 3
days. Settle stays possible after it, until the first refund claim flips the
table to Refunding.

**Eligibility** (at `join_stack`). In-person tables take any rig, but a bond
above 500 SKR needs a verified Seeker (tier 1, SGT re-verified);
`ATTESTED_ONLY` needs an unexpired attestation of level 1 or 2. Remote tables
are always attested-only and Seeker-only (SGT re-verified at join), are keyed
by the SGT mint, and have a lower bond cap.

**Limits, stated plainly.** The chain verifies signatures, not behaviour
(THREAT_MODEL §9).

* A check-in must land in its round: a round nobody checks in for is a gap,
  even if the phone was down (fail-closed; grace absorbs a few).
* A BREAK that lands in `end_round` after the seat's last check-in that round
  is not seen unless another check-in lands that round.
* One heartbeat counts at every table the rig sits at.

### 11.6 Focus Bond

The bond is tied to one shift, identified by `(rig, shift_id, start_round,
start_ts)`. It resolves from that shift's ShiftLog (§6.8):

| ShiftLog | Outcome |
|---|---|
| sealed, reason 0 `completed` | `release_focus_bond`: the owner gets the SKR back |
| sealed, any other reason (1 to 8) | `forfeit_focus_bond`: the SKR becomes a Bury lot |
| never sealable: the rig was closed while the shift was open, or the slot holds a later incarnation's log | `forfeit_focus_bond`, reason 255 abandoned |

Under the v1.1 `end_shift` rules, a soft break that resumed with a fresh
heartbeat (Cooling → Down) still seals `completed`, so it keeps the bond. A
hard break, a freeze, a lease lapse, or ending the shift early inside its
window does not. Both outcomes are permissionless and pay only the stored
owner or the Bury lot, so nobody, the owner included, can hold a bond
hostage.

### 11.7 Gift a Rig

| Step | Rule |
|---|---|
| create | the sender escrows 1 lamport to 10 SOL for a wallet or an SGT mint, expiring in 30 days |
| claim | before expiry; the wallet itself, or whoever holds that SGT at claim time (verified in the program) |
| refund | from expiry; anyone may trigger it; everything goes to the sender |

The escrow binds to the SGT **mint**, not to a `.skr` name, so a later name
transfer cannot redirect it. Solana Mobile can move an SGT (it holds a
permanent-delegate authority); the gift then follows the SGT's new holder, by
design.

### 11.8 Bury auction (no oracle)

* **One pooled lot.** Stack and Focus Bond forfeits are deposited into the
  Bury SKR vault. Each deposit adds to `lot_skr`.
* **Restart.** A deposit **restarts** the auction when the lot was empty or
  the deposit is at least as large as what was on offer (`amount >=
  lot_before`); a smaller deposit joins the running auction at its current
  price and clock (and its `BuryLotAdded` repeats the running auction's
  `start_price` and `start_slot`). A restart sets `auction_start_slot = now` and
  `start_price = max(4 × last_clear_price, previous start_price / 2)` clamped
  to `[10,000, 10,000,000,000]`; before the first sale that is 100,000,000
  (§12.13).
* **Price** (ORE atoms per whole SKR) at slot `t`, in u128:
  `start − (start − floor) · min(t − start_slot, window) / window`, with
  `floor = 10,000` (1e-7 ORE per SKR) and `window = 216,000` slots. It never
  rises between deposits and reaches the floor, so lots always sell.
* **Cost** of `skr_amount` base units: `ceil(skr_amount · price / 10⁶)` ORE
  atoms, rounded in the lot's favour (at least 1 atom).
* **Partial buys** are allowed. The price schedule carries on, and the price
  of the last sale of at least 10 SKR (`MIN_ANCHOR_SKR`) becomes
  `last_clear_price`; a smaller sale leaves it unchanged.
* **What happens to the ORE.** ORE `bury` moves it to ORE's Treasury, sends
  `cost / 10` to ORE's stake program through the stake program's `distribute`, and
  burns the rest (`bury.rs:35-74`). heads_down checks the burn against the
  ORE supply. Reports must say "90% burned, 10% to ORE's stake program", never "100%
  burned".
* The "grams" address `GHRBYPA4…` is not used (docs/ORE.md §10).

#### 28 `propose_governance`

Accounts: `0 [s] governance | 1 [w] Config`.

Data: `0 tag | 1 new_governance [32]`.

* The signer must be `Config.governance` (`Unauthorized`, 5).
* `new_governance` must be neither all-zero nor the current governance
  (`InvalidInstruction`, 0).
* It sets `pending_governance`, `pending_governance_eta_slot = slot +
  864,000` and `pending_governance_eta_ts = unix_timestamp + 259,200`: the
  timelock of `propose_config`. A new proposal replaces the pending one and
  restarts the clock.
* Nothing else changes. Emits **GovernanceProposed**.

#### 29 `accept_governance`

Accounts: `0 [s] the pending governance | 1 [w] Config`. Data: `0 tag`.

* A rotation must be pending (`InvalidInstruction`).
* The signer must be `pending_governance` (`Unauthorized`). Nobody else can
  complete a rotation: not the current governance, not a third party.
* `slot >= pending_governance_eta_slot` and `unix_timestamp >=
  pending_governance_eta_ts` (`TimelockNotElapsed`, 19).
* `governance = pending_governance`; the three rotation fields return to
  zero.
* A pending `propose_config` proposal is cleared (`pending_exists = 0` and
  the other `pending_*` fields zero): it was the outgoing governance's, and
  the new one proposes its own. `paused` is not touched.
* Emits **GovernanceAccepted**.

#### 30 `cancel_governance`

Accounts: `0 [s] governance | 1 [w] Config`. Data: `0 tag`.

The signer must be the **current** governance (`Unauthorized`), and a rotation
must be pending (`InvalidInstruction`). The three rotation fields return to
zero. Emits **GovernanceCancelled**.

**The timelock: slots and time.** A timelock (of a config proposal or of a
rotation) has two halves and ends when **both** have passed:

* 864,000 slots (`TIMELOCK_SLOTS`, the v1.1 rule);
* 259,200 seconds, 72 hours, of `Clock.unix_timestamp` (`TIMELOCK_SECS`,
  v1.3).

v1.1 chose 864,000 slots as "72 h at 300 ms slots". Mainnet's slots are
shorter than that now: 267.7 ms on average over 51,546 slots on 2026-10-01,
so 864,000 of them pass in about 64 hours, and at 200 ms they would pass in
48. A count of slots is only a duration while the slot time holds still. The
time half makes every timelock at least 72 hours of cluster time whatever
the slot time is; the slot half stays as a floor that does not depend on the
cluster clock (it is the one that binds on a local validator at 400 ms:
96 h). A client that waits for a timelock reads both etas.

**What the two steps buy.**

* A stolen governance key cannot move governance at once: the successor is
  public in the Config for the whole timelock (at least 72 hours), during
  which the real governance can cancel.
* A mistyped successor cannot lose governance: an address nobody controls can
  never sign `accept_governance`, so `Config.governance` stays where it is.
* **The emergency pause stays immediate.** Until the successor accepts, the
  current governance keeps every power: `propose_config` with `paused = 1`
  still pauses in the same slot (§6.6). The successor has no power before it
  accepts, and all of them from the slot it does.
* The successor may be a program-derived address (a multisig vault): it
  accepts through a CPI in which it is a signer.

2 []  FocusBond PDA ["bond", log.rig, log.shift_id]   (must not hold a bond)
```

Data: `0 tag`. See §12.5.

### 12.4 The Rig tombstone: shift ids and counters never go back

**The bug (v1.1 §10).** `close_rig` returned the Rig PDA to System, so a rig
registered again for the same wallet started with `shift_id` 0 and
`hb_counter` 0. Three things followed:

* `end_shift` of the new shift 1 failed, because the first life's ShiftLog
  already sat at `["shift", rig, 1]`. The rig could not seal a shift again.
* Old P-256 messages became valid again on a rig registered with the same
  key. They bind the rig address, the shift id and a counter that must exceed
  `hb_counter`; all three matched. A BREAK or FREEZE once signed for the old
  shift 1 could be replayed by anyone against the new shift 1 (the signatures
  are public in the old transactions), breaking it and forfeiting its Focus
  Bond. A PLAN, whose preimage has no shift id, could arm the rig.
* A Stack seat bound to shift `k` (§11.5) accepted a brand-new shift `k`. A
  player whose BREAK was recorded could freeze, close, re-register and arm,
  and the seat counted on as if nothing had happened.

**The fix.** `close_rig` zeroes the rig and, unless `shift_id == 0` and
`hb_counter == 0`, shrinks it to a RigTombstone holding those two counters and
`last_dug_round`. `register_rig` on a tombstone tops its lamports up to a
Rig's rent from the authority, grows it back to 384 bytes, and initializes a
fresh Rig whose `shift_id`, `hb_counter` and `last_dug_round` are the
tombstone's. Everything else starts as in
a first registration (state Idle, tier 0, no caps, no streak; the key and the
attestation are the ones in this `register_rig`). So for a given rig address:

* `shift_id` only grows, so `["shift", rig, id]` and `["bond", rig, id]` are
  never reused and a seat's bound shift can never be armed again;
* `hb_counter` only grows, so no P-256 message is accepted twice, whichever
  key the rig carries;
* `last_dug_round` survives, so closing and registering again inside one ORE
  round cannot dig that round a second time (past the per-round cap).

A tombstone is not a Rig: every instruction that takes a Rig refuses it
(`InvalidAccountTag`), `stack_checkin` treats its seat as a closed rig (rule
1 of §11.5), and `forfeit_focus_bond` treats its bond as abandoned.

**Why this design.** Two others were considered.

* *Derive the first `shift_id` from the Clock slot.* It changes every fresh
  rig's ids (and every golden vector that carries one), still collides when a
  rig is closed and registered again inside one slot, and does not stop the
  PLAN replay, which needs the counter, not the shift id.
* *A separate tombstone PDA.* It needs a new account in `close_rig` and in
  `register_rig`, which breaks both instructions for every existing client.
  The Rig PDA is already per wallet and already in both account lists.

**Cost.** The tombstone keeps the rent of 32 bytes (1,113,600 lamports at the
test suite's rent; 812,800 at mainnet's rent on 10 October 2026)
until the wallet registers again, when it counts towards the new Rig's rent;
lamports sent to a tombstone are returned by the next `close_rig`. Rigs closed
by an earlier build left no tombstone.

### 12.5 ShiftLog rent recovery

* `end_shift` stores `payer_prefix`, the first 16 bytes of the caller's
  address. The log has no room for 32; 128 bits bind the refund as firmly,
  since a second address with that prefix is a 2^128 search.
* `close_shift_log` works from `now >= end_ts + 2,592,000` (30 days),
  otherwise `ShiftLogNotExpired` (49).
* The lamports go only to an address with that prefix (`Unauthorized`): the
  wallet that ended its own shift, or the crank that sealed it. Returning them
  to the rig's authority instead would hand it the rent of every shift a crank
  seals.
* A log sealed before v1.3 has a zero prefix. Its rent goes to the rig's
  authority, proven without the Rig account: `find_program_address(["rig",
  recipient])` must equal `log.rig`.
* Account 2 must be the canonical FocusBond PDA of `(log.rig, log.shift_id)`
  (`InvalidSeeds`) and must not hold a bond (`ShiftLogInUse`, 50). A bond
  resolves from this log (§11.6): without the check, closing the log of a
  completed shift would make its bond look abandoned and let anyone forfeit
  it. Release or forfeit the bond first; both are permissionless.
* The log is zeroed and returned to System. Its address is never written
  again, because the rig never reuses that shift id (§12.4).
* Emits **ShiftLogClosed**. The shift's history stays in its `ShiftEnded` /
  `ShiftEndedV2` events.

### 12.6 Attestation: checked wherever it is relied on

A rig's attestation is **live** at slot `s` iff `attestation_level` is 1 or 2
and `attestation_expiry_slot > s`. An expired attestation counts as none.

The program relies on the attestation in exactly two places, and both now ask
that one question:

| Where | Since | Rule |
|---|---|---|
| `join_stack` at an `ATTESTED_ONLY` table (every `REMOTE` table is one) | v1.2 | live at the join, else `StackIneligible` (36) fails the transaction |
| `stack_checkin` at an `ATTESTED_ONLY` table | **v1.3** | live at this check-in, else the seat's `StackCheckin.result` is 36 |

In the per-seat rule of §11.5 the new check sits between rows 6 and 7:

| # | Condition | Result | Effect on the seat |
|---|---|---|---|
| 6b | attested-only table and the rig's attestation is not live | 36 StackIneligible | none: not counted, not broken; the heartbeat in the entry is not consumed |

It applies in verify mode and in observe mode. Counting resumes as soon as the
rig is attested again (`rotate_key` with a fresh voucher).

**Why.** Checked only at the join, the attestation could be shed afterwards:
`rotate_key` without a voucher replaces the key with any software key (and
resets the level to 0), and its scripted heartbeats kept counting to the end
of the window. A voucher could also run out days before the window did.

**What a client must do.** A voucher that expires inside the window stops the
seat counting, and the wallet (which must sign `rotate_key`) is not there at
night. Before joining an attested-only table, check that
`attestation_expiry_slot` is comfortably past the window's end, and renew the
attestation first if it is not.

**The Seeker tier** (`tier == 1`) is not an attestation and has no expiry.
Where holding an SGT grants something (`join_stack` at a remote table or above
the guest bond cap, `claim_gift` for an SGT gift), the program verifies the
SGT itself in that instruction, which is stronger than any stored date.

### 12.7 P-256 key uniqueness (THREAT_MODEL §6.8): evaluated, not built

§6.8 recommends that a P-256 key back only one rig, enforced by a marker PDA
keyed by the hash of the public key. v1.3 does not build it.

**What it would buy.** Nothing the program does not already have:

* *Replay across rigs* is impossible: every preimage binds the rig address.
* *An unattested key* is a number anyone can generate. "One rig per software
  key" is satisfied by generating another key, so the marker would bind
  nothing to a device.
* *An attested key* is already bound to one wallet, and so to one rig. The
  registrar accepts a Key Attestation only if its challenge equals
  `SHA-256("HDattest" || authority || nonce)` for a single-use nonce; the
  challenge is fixed in the key's certificate when the key is generated; the
  voucher names that authority; `register_rig` and `rotate_key` rebuild the
  voucher message from the wallet that signs; and a wallet has one Rig PDA.
* *Money at stake* depends on a key's identity only at attested-only Stack
  tables. What those needed was for the attested key to stay the key that
  proves every round, which is §12.6.

**What it would cost.**

* Public keys are public (in every Rig account and precompile instruction),
  and `register_rig` takes a key without proof of possession. A marker
  claimed by whoever registers a key first would let anyone lock a user's key
  by registering it under a throwaway rig. Closing that hole needs a P-256
  signature at registration: a new message kind, a precompile instruction in
  the onboarding transaction, and a new failure mode there.
* A marker account in `register_rig`, `rotate_key` and `close_rig` changes
  three frozen account lists, and about 0.0014 SOL of rent per rig.

Revisit this if a later feature gives an unattested key value to someone other
than its owner.

### 12.12 Not implemented or open in v1.3

* The Stack and Focus Bond outcomes of a night depend on its heartbeats being
  landed: a crank (anyone's) that lands none for a rig costs that rig its
  rounds. The program cannot tell a phone that was up from a relay that was
  down. A rig's owner can run a crank, and `record_heartbeats` and
  `stack_checkin` are permissionless.
* An in-person Stack table is open to any rig that can pay the bond: the
  program does not check that the players are in one room. The app only
  offers such tables over Nearby; a table id shared wider than that can be
  joined by a scripted guest rig.
* A shift that never landed a heartbeat is sealed `lease_lapse` by whoever
  ends it first once its window is over (the 3-round grace of §12.13 needs a
  lease to count from).

* A tombstone's rent stays at the Rig PDA until the wallet registers again;
  there is no instruction to delete a tombstone.
* A voucher that expires inside a Stack window stops the seat counting
  (§12.6). The program does not refuse a join whose voucher cannot outlast
  the window: it cannot know how many slots the remaining rounds will take.
* Governance has no multi-step recovery beyond cancel: if the current
  governance key is lost before a rotation is accepted, only the pending
  governance (after the timelock) or a program upgrade can act.
* `propose_config` and `apply_config` emit no events.


### 12.13 Audit fixes (2026-10-03, before the first deployment)

A security review of v1.3 ran before anything was deployed. Seven rules were
tightened. None adds a tag, an event or an error, no instruction changed its
bytes or its account list, and no account changed its size. They are part of
v1.3: no build without them was ever deployed.

| # | Rule | Before | Now | Error when refused |
|---|---|---|---|---|
| 1 | Crank reimbursement (§6.5) | paid after any real deploy | paid only if the Executor received at least `crank_fee` in the same dig | none: the dig counts, the transfer is skipped |
| 2 | P-256 counter (§4.1) | any value above `hb_counter` | above `hb_counter` by at most 2^32 | 6 `InvalidHeartbeat` (a skip code in `dig`, `record_heartbeats` and `stack_checkin`) |
| 3 | Voucher lifetime (§4.2) | any `expiry_slot` in the future | at most 25,920,000 slots ahead | 21 `InvalidAttestation` |
| 4 | Permissionless `end_shift` (§5, tag 11) | window over and `lease_to_round < Board.round_id` | window over and `lease_to_round + 3 < Board.round_id` | 5 `Unauthorized` |
| 5 | Bury auction (§11.8) | every deposit restarted price and clock at `4 × last_clear_price`; every sale set `last_clear_price` | a deposit restarts only an empty lot or one it at least doubles, never below half the previous start; only a sale of 10 SKR or more sets `last_clear_price` | none |
| 6 | Rig tombstone (§12.4) | kept `shift_id` and `hb_counter` | also keeps `last_dug_round` (the 8 bytes that were reserved) | none |
| 7 | `dig` and `record_heartbeats` with a closed rig (§6.1, §6.2) | failed the whole transaction | skip that rig | 4 `InvalidAccountTag` as a skip code |

**Why, one line each.**

1. ORE charges the Automation fee on a Miner's first deploy of a round only.
   A rig whose owner had already deployed by hand paid the Executor nothing,
   and the cranker was still paid from the shared float: a wallet cranking its
   own rig could draw the float down to its floor.
2. One signed message with `counter = u64::MAX` left no larger value, so the
   phone key could never sign for that rig again. An app that read
   `hb_counter` from a dishonest RPC could be made to sign one.
3. A registrar key that leaked could sign vouchers valid for ever, and they
   would have outlived its rotation.
4. A Stack seat uses one-round leases, so at every round boundary its lease
   was behind the Board until the next heartbeat landed. In that gap, once the
   plan window was over, an opponent could end the rig's shift and the seat
   could never count again.
5. A purchase of one base unit at the floor set the price every later lot
   started from, and a dust forfeit put a running auction back to its start
   price for the cost of a signature.
6. Ending a shift, closing the rig and registering it again inside one ORE
   round reset the once-per-round rule.
7. A wallet that froze and closed its rig just before a batch landed made
   every other rig in that batch miss the round, at the price of one
   transaction fee.

**What a client must do.**

* A crank waits for the 3-round grace before it seals a shift, and does not
  expect a reimbursement for a rig whose Miner already deployed this round.
* The app counts up by one from the Rig's `hb_counter`, and refuses an
  `hb_counter` that is implausibly far from the last one it used.
* The registrar issues vouchers of at most 25,920,000 slots (its default,
  6,480,000, is a quarter of that).
* An indexer that shows the Bury auction takes `start_price` and `start_slot`
  from `BuryLotAdded` as before: they are the auction's values after the
  deposit, and they are the old ones when the deposit joined a running
  auction. It must not assume that every deposit restarts the clock.
