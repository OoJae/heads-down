## Provenance

`ThunkSoundAssetTest` regenerates the WAV in memory on every unit-test run and fails if the committed
file differs by a single byte, so the asset in the APK is always the one the code describes. After
changing the synth:

```sh
cd android
HD_REGENERATE_SOUNDS=1 ./gradlew :surface:haptics:testDebugUnitTest
```

## What it is

A sine that glides from about 170 Hz to 95 Hz with a 50 ms decay, a wooden overtone at 2.76× that dies
within ~20 ms, and a 3 ms low-passed noise click for the attack. Phone speakers roll off below
roughly 150 Hz, so the body sits just above that: it reads as a soft "thunk" on a nightstand rather
than a beep. `StrictMath` keeps the output bit-identical on every JVM.

## When it plays

Only for `HapticCue.ARM_THUNK`, and only when all of these hold:

- the motor cannot compose the thunk's primitives (`Vibrator.areAllPrimitivesSupported` is false),
  which is the case for basic motors such as the Redmi 14C's;
- the ringer is in normal mode (never in silent or vibrate mode);
- the user has not turned the audible thunk off.

It is played with `USAGE_ASSISTANCE_SONIFICATION` at 60% volume, so Do Not Disturb still applies.
No cue plays per ORE round; see `HapticGovernor`.
